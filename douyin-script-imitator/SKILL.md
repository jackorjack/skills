## 何时使用（触发条件）

当用户意图为**仿写/模仿/改写/参考已有视频**时触发，典型信号：

- 用户提供了抖音/短视频链接，并要求「仿写」「模仿」「改写」「借鉴」「参考」「照着写」
- 用户说「像这个视频一样写个脚本」「按这个风格来」
- 用户发来链接 + 任何暗示复用结构/风格/节奏的表述
- 用户说「拆解这个视频」「分析这个视频再仿写」


## 完整工作流

### 第1步：解析抖音视频元数据

提取：标题、作品描述、标签、内容形式、高频关键词、评论热点词、账号信息（昵称/粉丝/获赞/类型）、点赞/评论/收藏量。

**操作（按优先级）：**
1. **Playwright Stealth 脚本（首选）：** 使用`scripts/fetch_video_detail.js`，通过API响应拦截+video元素轮询双保险获取视频真实CDN地址及完整元数据。在本技能目录下直接运行：
   ```bash
   cd skills/douyin-script-imitator && node scripts/fetch_video_detail.js <aweme_id或完整URL>
   ```
   脚本支持传入 aweme_id 或完整抖音链接（含短链），自动解析。输出 JSON 包含：fullTitle, videoSrc（真实CDN地址）, authorName, followers, likes, comments, shares, publishDate, tags。

2. **OpenClaw browser（备选）：** 当Playwright脚本不可用（如缺依赖）时使用。`browser`打开链接→`snapshot`提取页面信息→`screenshot`截取画面用于第2d步。**注意：** `act evaluate`取`<video>.currentSrc`可能返回blob URL而非真实地址，需轮询等待（见下方注意事项）。

3. **web_fetch（兜底）：** 通常只能拿空壳，效果有限

4. 短链接（`v.douyin.com/xxx`）两种方式都会自动跳转

5. 获取视频链接的时候不要向用户输出登录的截图

**⚠️ 浏览器使用注意事项（OpenClaw browser备选时）：**
- 抖音页面是重SPA，标签页堆积会导致CDP超时。操作前先检查并清理多余标签页（`browser tabs`查看，关闭非必要页面）
- 每次操作完成后立即关闭标签页，避免残留
- 如果snapshot/evaluate超时，先清理标签页再重试
- `<video>.currentSrc`在视频初始化阶段返回`blob:` URL，需等待MSE加载完成后才会更新为真实CDN地址。如果取到blob URL，等2-3秒再取一次
- snapshot中不包含video源地址，必须用`act evaluate`提取

**标题与作品描述的区分规则：**

抖音PC网页端将标题和描述合并为一个`<h1>`展示，无法从DOM直接区分。按以下规则推断拆分：

1. **标签提取**：以`#`开头的文本块，单独提取为标签列表
2. **标题推断**：去除标签后，第一个句号`。`或感叹号`！`之前的短句作为标题
3. **描述推断**：标题之后、标签之前的剩余内容作为作品描述
4. **无标点情况**：如果整段无句号/感叹号，字数≤20则整段作为标题，描述为空

示例：
```
原始heading：带大家在线验厂，参观下我们的塑料瓶生产工厂！食品瓶，肉松瓶，糖果瓶，鱼肠瓶，蜂蜜瓶，饮料瓶，果汁瓶，奶茶瓶，化妆品瓶生产厂家/工厂 #工厂实拍视频 #源头实力厂家 #塑料制品 #塑料瓶 #专业生产厂家

→ 标题：带大家在线验厂，参观下我们的塑料瓶生产工厂！
→ 描述：食品瓶，肉松瓶，糖果瓶，鱼肠瓶，蜂蜜瓶，饮料瓶，果汁瓶，奶茶瓶，化妆品瓶生产厂家/工厂
→ 标签：#工厂实拍视频 #源头实力厂家 #塑料制品 #塑料瓶 #专业生产厂家
```
### 第2步：提取音频并转写口播文案

**核心步骤，优先于页面字幕提取。**

#### 2a. 获取视频源地址并下载视频

**获取视频源地址（按优先级）：**

**方式1（首选）：复用第1步结果**
- 如果第1步用 Playwright 脚本 → JSON 中 `videoSrc` 已是真实 CDN 地址，直接用
- 如果第1步用 OpenClaw browser → 用 `browser act evaluate` 从页面提取，轮询等待 blob 消失：
  ```javascript
  const src = document.querySelector('video')?.currentSrc || document.querySelector('video')?.src || ''
  // 如果返回 blob: 开头，等2-3秒再取一次
  ```

**方式2（兜底）：单独运行 Playwright 脚本**
```bash
cd skills/douyin-script-imitator && node scripts/fetch_video_detail.js <aweme_id或URL>
```

**下载视频：**
```bash
curl -L -o /tmp/douyin_video.mp4 "<视频下载地址>" -H "User-Agent: Mozilla/5.0" -H "Referer: https://www.douyin.com/"
```

**降级方案：**
- curl 403 → 检查视频源URL是否已过期，重新获取
- 以上方式全部失败 → 回退到页面字幕/描述提取，跳过音频转写

#### 2b. 提取音频
```bash
ffmpeg -y -i /tmp/douyin_video.mp4 -acodec pcm_s16le -ar 16000 -ac 1 /tmp/douyin_audio.wav 2>/dev/null
```

#### 2c. 语音转写

```bash
python3 scripts/transcribe.py $SILICONFLOW_API_KEY /tmp/douyin_audio.wav
```
SiliconFlow API偶发500错误，脚本已内置重试逻辑（间隔5秒，最多3次）。如全部失败→回退到页面字幕/描述提取，跳过音频转写。

#### 2d. 画面分析

从视频中截取3个关键时间点的画面（开头/中间/结尾），分析画面信息用于仿写脚本的「画面脚本」列：

**操作步骤：**
1. 用 `browser` 打开视频页面，拖动进度条到 0%、50%、90% 位置各截一张图
2. 对每张截图提取：
   - **场景**：在哪里拍的（工厂车间/办公室/户外/展厅/演播室）
   - **人物/主体**：谁在画面中、在做什么动作
   - **景别**：特写/近景/中景/全景/远景
   - **运镜**：固定/推拉/摇移/跟拍/手持
   - **转场**：硬切/淡入淡出/滑动/无转场（一镜到底）
3. 汇总3张截图，判断整体画面风格（如：固定机位口播 / 手持跟拍工厂 / 产品特写+文字叠加）

### 第3步：获取企业信息（记忆优先 → 文件兜底 → 同步兜底）

**核心原则：优先从 memory 检索，避免重复加载大文件，命中即用。**

执行顺序：
1. **memory_search 检索**：用以下 query 组合并发检索企业信息（`corpus=memory`），每轮至少 3 条 query。**注意：query 中的占位词（如「企业名称」）需替换为实际企业名称后执行检索**：
   - `"[企业名称] 品牌定位 核心业务 产品线"` → 获取企业基础信息和产品/服务线
   - `"[企业名称] 产品卖点 差异化优势 目标客户 用户痛点"` → 获取核心卖点和客户画像
   - `"[企业名称] 企业实力 客户案例 数据 信任背书"` → 获取实力数据和案例素材
2. **memory_get 补全**：检索命中的片段若被截断（含"…"），用 `memory_get` 按路径+行号拉取完整内容
3. **文件兜底**：若 memory 未命中或内容明显不足（少于 3 条有效信息片段），降级读取 `workspace/wiki/` 目录下 md 文档
4. **同步兜底**：若 workspace/wiki/ 目录下无文档，执行技能 `enterprise-kb-sync` 将企业知识库同步到本地，同步完成后回到步骤 1 重新走记忆检索

**提取关键信息**：公司名/行业/规模、主推业务/卖点、目标客户/痛点、差异化优势、目标市场、内容方向。

**注意**：
- memory_search 返回的 `snippet` 可能不完整，关键信息必须用 memory_get 补全
- 企业 wiki 文档已自动索引到 memory，优先走记忆通道

**压缩为≤150字摘要**，用于仿写参考。

### 第4步：识别视频类型并拆解结构

#### 4a. 判断视频类型

根据原视频内容判断类型，分为两大类：

**产品/业务类**：展示产品、工厂、服务、案例，以获客转化为目的
- 特征：讲产品卖点、应用场景、客户案例、工厂实力、生产工艺
- 技巧：数字法、对比法、场景法、痛点法

**观点/IP类**：输出行业观点、认知、经验，以建立人设和信任为目的
- 特征：讲行业现状/趋势/误区、创业经历、经营理念、反常识观点
- 技巧：反常识法、共情法、权威法、故事法、对比法
- 典型场景：老板出镜口播、行业认知输出、避坑指南、经验分享

#### 4b. 观点类视频 → 检索 IP 观点文案参考库

**仅当原视频为观点/IP类时执行此步。**

从 memory 检索企盛 IP 观点文案库，找到风格/结构最接近的参考文案：

```bash
memory_search query="原视频核心观点关键词 IP观点" corpus=memory maxResults=5
```

**检索策略：**
1. 提取原视频的核心观点关键词（1-3个词），组合 "IP观点" 一起搜索
2. 若首轮命中不足，换关键词再搜一轮
3. 用 `memory_get` 拉取最匹配的 1-2 条完整文案作为仿写参考

**参考维度：**
- 观点切入角度（反常识/行业洞察/经验总结）
- 论述结构（观点→论证→案例→总结）
- 语言风格（犀利/沉稳/共情/权威）
- 钩子类型（反常识/痛点/数据/故事）

#### 4c. 拆解原视频结构

逐句拆解，格式：`句N：[原文] → [功能] → [技巧]`

**功能类型定义：**

| 功能 | 定义 | 示例 |
|------|------|------|
| 钩子 | 开头抓注意力，制造好奇心或冲击力 | 「做了10年加工，今年差点关门」 |
| 痛点 | 描述客户遇到的问题/困扰 | 「每次找供应商都要比价3天」 |
| 共鸣 | 让目标客户觉得「说的就是我」 | 「做工厂的都知道，账期是个大问题」 |
| 方案 | 给出解决思路或产品方案 | 「我们把这个环节标准化了」 |
| 卖点 | 展示产品/服务的核心优势 | 「良品率做到99.7%，行业里不多见」 |
| 信任 | 建立可信度（资质/案例/数据） | 「服务过37家上市公司」 |
| 引导 | 引导用户思考或产生兴趣 | 「你猜我们怎么解决的」 |
| CTA | 明确的行动号召 | 「评论区扣1，我把方案发你」 |

**技巧类型定义：**

| 技巧 | 定义 | 示例 |
|------|------|------|
| 数字法 | 用具体数字增强说服力 | 「交付周期从15天缩到5天」 |
| 对比法 | 前后/优劣/新旧对比制造反差 | 「别人报3万，我们8千搞定」 |
| 场景法 | 描述具体使用场景代入 | 「凌晨3点设备坏了，打电话我们15分钟响应」 |
| 反问法 | 用反问引发思考 | 「你的供应商能48小时出货吗」 |
| 共情法 | 表达理解客户的处境 | 「我知道你被上家坑怕了」 |
| 权威法 | 引用资质/认证/行业地位 | 「我们有ISO 13485医疗认证」 |
| 紧迫法 | 制造合理的时间/数量紧迫感 | 「这个月产能还剩最后3个档期」 |
| 利益法 | 直接说明客户能获得的好处 | 「省下的模具费够你再开一条线」 |
| 反常识法 | 抛出反直觉观点制造冲击 | 「做代工不丢人，不会做才丢人」 |
| 故事法 | 用真实案例/经历讲述 | 「去年有个客户，找了5家都不行...」 |

### 第5步：仿写角度选择 → 用户确认 → 生成脚本

#### 5a. 选择仿写角度并展示给用户确认

根据视频类型，从 `references/script-angles.md` 中选择3个不同角度：

| 类型 | 优先角度 | 说明 |
|------|---------|------|
| 观点/IP类 | 反常识、行业揭秘、故事共鸣、对比碾压 | 侧重观点输出和认知建立 |
| 产品/业务类 | 痛点放大、卖点直击、场景代入、数据说话 | 侧重获客转化和信任建立 |

按以下格式展示给用户，**暂停等待确认**：

```
🎯 仿写角度方案

| 脚本 | 角度 | 为什么选这个 |
|------|------|-------------|
| 脚本1 | [角度名] | [结合原视频风格和企业特点说明] |
| 脚本2 | [角度名] | [说明] |
| 脚本3 | [角度名] | [说明] |

确认后开始生成，或指定要调整的角度。
```

用户确认后进入 5b。如果用户指定了不同角度，按用户要求调整后再进入 5b。

#### 5b. 生成3条脚本

用户确认角度后，按原视频风格读取1个示例文件作为仿写参考：
- 大字报（口播展示卖点）→ `references/imitation-example-oral.md`
- 危机+方案（事故→解决方案）→ `references/imitation-example-crisis.md`
- 工厂探店/Vlog（边走边讲）→ `references/imitation-example-vlog.md`

**仿写要求**

- 严格按原视频句式结构、节奏、功能分布仿写,句数/功能/节奏一致
- 每句「功能」和「技巧」与原视频一致
- 内容替换为企业产品/卖点/场景/客户/数据
- 融入企业核心卖点和差异化优势
- **观点类视频额外要求**：仿写时融合第4b步检索到的 IP 观点文案的论述风格和切入角度，保持观点输出的深度和专业感
- 仿写后必须通顺,拗口/生硬必须调整，宁可多一字不可卡一秒
- 标签：围绕品牌+产品+行业+人群+热点关键词
- 目标用户：文案针对客户人群，注意人称

### 第6步：脚本审校（广审合规 + AI味检查）

仿写完成后，对3条脚本逐条进行5项审校。发现问题直接修改，最后输出修改清单供用户确认。

#### 6a. 口语化检查

大声朗读测试：每句超过15字考虑拆短句。检测并修正书面词汇：

| ❌ 书面 | ✅ 口语 |
|--------|--------|
| 进行操作/进行展示 | 点击/看一下 |
| 接下来我们将 | 我们来 |
| 综上所述/总而言之 | 直接说结论 |
| 值得注意的是 | （删掉，直接说） |
| 充分利用/显著提升 | 用好/好了很多 |

#### 6b. 钩子强度评估

检查每条脚本前3秒：
- 是否有明确钩子（反常识/痛点/数据/场景/悬念/利益）
- 是否与目标客户匹配
- 是否能制造好奇心/紧迫感/共鸣
- 弱钩子标记并给出改写建议

#### 6c. 广审合规检查（重点）

**① 绝对化用语（必须删除/替换）**：
- ❌ 最好/第一/100%/绝对/唯一/顶级/全网最低/行业领先
- 替换为客观描述：「行业前列」→「做了XX年」，「最好」→「靠谱的」

**② 功效承诺措辞**：
- ❌ 治好/根治/永久/彻底解决/包用/终身
- ❌ 具体时间+具体功效（如「7天见效」「60秒缓解」）
- ✅ 替换为模糊体感：「用了之后感觉好多了」「用了一阵子有明显变化」
- 即使数据来自官方/检测报告，投放素材中也不能直接使用具体数字+功效

**③ 对比和贬损**：
- ❌ 「比XX品牌好」「吊打竞品」「别的厂家都不行」
- ❌ 虚假对比（编造竞品缺点）
- ⚠️ 可以说「比传统工艺效率高」，但不能点名贬低具体同行

**④ 虚假紧迫感和诱导**：
- ❌ 「不买就亏了」「错过再等一年」「最后XX个名额」（无真实依据）
- ❌ 未标注的演员扮演使用者/专家
- ✅ 真实限时活动可以提，但需有实际依据

**⑤ 制造业B端特殊合规**：
- 资质/认证声明必须有据可查（ISO/CE/专利号等，不能编造）
- 产能数据/客户案例必须真实（不能编造合作品牌名）
- 不暗示替代专业服务（如「不用找代理了」「不用验厂了」）

#### 6d. AI味检查（6大AI腔）

**① 套话连篇**：
- ❌ 「在当今时代」「值得注意的是」「众所周知」「随着...的发展」
- 检测：连续2句以上套话 → 删除或改写

**② AI句式**：
- ❌ 「不是...而是...」「不仅...而且...」连续使用
- ❌ 「无论...都...」「与其...不如...」过度使用
- 检测：同一句式出现2次以上 → 拆散重组

**③ 书面词汇**：
- ❌ 显著提升/充分利用/有效改善/深度赋能/全方位/多维度
- ✅ 好了很多/用好/感觉好多了/全包了/各方面

**④ 结构机械**：
- ❌ 过度使用「首先、其次、最后」「第一、第二、第三」
- ✅ 用自然过渡：「先说...」「再就是...」「还有一点」

**⑤ 态度中立**：
- ❌ 「具体取决于实际情况」「各有优劣」「因人而异」
- ✅ 给明确判断：「选这个准没错」「对于XX行业来说更合适」

**⑥ 细节缺失**：
- ❌ 大词多、具体细节少（「质量优异」但没有具体数据/场景）
