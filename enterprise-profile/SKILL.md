## 何时使用
- 用户要求梳理企业信息、产品卖点、竞争优势、企业关键词
- 被 `dazibao-script` / `video-script` 技能引用（作为前置步骤）

## 流程

### Step 1: 读取企业资料（记忆优先 → 文件兜底 → 同步兜底）

**核心原则：优先从 memory 检索，避免重复加载大文件，命中即用。**

执行顺序：
1. **memory_search 检索**：用以下 query 组合并发检索企业信息（`corpus=memory`），每轮至少 3 条 query：
    - `"企业名称 品牌定位 核心业务 产品线"` → 获取企业基础信息和产品线
    - `"技术壁垒 核心性能 适用场景 用户痛点"` → 获取产品卖点和行业信息
    - `"客户案例 服务数据 行业影响力 竞争优势"` → 获取信任背书和案例
    - 若企业有明确行业关键词（如"鞋垫""机械设备"），追加 `"{行业关键词} 产品 工艺 应用场景"`
2. **memory_get 补全**：检索命中的片段若被截断（含"…"），用 `memory_get` 按路径+行号拉取完整内容
3. **文件兜底**：若 memory 未命中或内容明显不足（少于 3 条有效信息片段），降级读取 `workspace/wiki/` 目录下 md 文档
4. **同步兜底**：若 `workspace/wiki/` 目录下无文档，执行技能 `enterprise-kb-sync` 将企业知识库同步到本地，同步完成后回到步骤 1 重新走记忆检索

**注意**：
- memory_search 返回的 `snippet` 可能不完整，关键信息必须用 memory_get 补全
- 不要仅凭 memory_search 的 snippet 判断信息充足，需确保读取到完整段落
- 企业 wiki 文档已自动索引到 memory，优先走记忆通道

### Step 2: 企业及产品梳理

生成四部分，每部分必须从资料中提取，资料不足处标注「建议补充」，不要编造：

**1. 用户分析**（按产品线/行业拆分）

每个行业输出表格：应用场景 | 用户痛点 | 业务优势 | 用户爽点
- 场景要具体（谁+什么情况+需要什么）
- 痛点要量化（数字+对比+后果）
- 优势要差异化（对应痛点的独特方案）
- 爽点要可感知（省了/赚了/解决了什么）
- 每个行业 3-5 个场景，从资料中提取

产品分类术语自动选择：制造业→产品系列/产品线，电商→商品类目，服务→服务类型/解决方案

**2. 产品卖点梳理**

每类产品输出表格：应用场景 | 核心卖点 | 差异化卖点 | 口语化传播话术

**3. 企业优势梳理**

列表输出：企业实力 | 信任背书 | 可包装方向 | 其他优势（可搜索补充）

**4. 企业关键词**

企业关键词 = 与企业本身直接相关的可检索词汇，覆盖四类：品牌词（企业简称/品牌名）、产品词（产品名称、品类、材质、功能特征）、行业词（所属行业与细分领域）、人群/场景词（目标客户身份与应用场景）。从企业名称、品牌定位、产品线、行业属性、服务对象中提取，而非从企业优势/业务模式中提取。

**禁止混入以下五类词汇**（与行业无关，任何制造业企业均适用）：
- ❌  业务模式词：精密定制、非标定制、来图来样、私模开模、OEM、ODM（你卖的是"蠕动泵硅胶管"，不是"定制服务"）
- ❌  认证/资质词：ISO 13485、ISO 10993、USP Class VI、FDA、LFGB、GMP、万级洁净车间、铂金硫化、国家高新技术企业、专利（这些是企业实力背书，不是关键词）
- ❌  渠道/市场词：出口、跨境、医疗展会（CMEF/Medtec）、电商、爆款（关键词不描述在哪卖）
- ❌  品类概括词："硅胶制品""硅胶配件""医疗配件"太泛 → 应拆成具体产品词，如"蠕动泵管""呼吸管路""输液管路""密封圈""异形硅胶管"
- ❌  企业属性词：源头工厂、工厂、供应商、厂家、生产商、品牌方（无获客价值的泛称，≠企业关键词）

**自查方法**：输出企业关键词后，逐条问——「这个词能不能直接描述"企业是谁、做什么产品、服务谁"？」不能就删掉。

## 核心约束
- 企业信息不足时，标注「建议补充」，禁止编造
- 检索为空时明确告知"知识库暂无此内容"
- 不要将 SOUL.md / USER.md / AGENTS.md 等配置文件当作知识库内容

## 输出格式

```
# {企业名称} · 企业信息梳理

## 一、用户分析
（按行业/产品线拆分，表格）

## 二、产品卖点梳理
（按产品线，表格）

## 三、企业优势梳理
（列表）

## 四、企业关键词
（列表）
```
