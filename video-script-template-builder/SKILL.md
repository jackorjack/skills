# video-script 模板构建器

## 何时使用

用户拿到一份新行业的 docx 源文档（按 `引流型/种草型/转化型` 三份分开，或合一份），要把其中的选题示例拆成 `video-script` skill 能加载的 md 模板，并把主 `SKILL.md` 的选题表同步成与 docx 实际类别一致时使用。

典型信号：
- 「海盛威的 docx 整理一下建模板」
- 「把这个新行业的引流/种草/转化 docx 拆成模板」
- 「同步一下 video-script 的选题表」
- 「给 xx 行业建一套视频脚本模板」

## 依赖

- 目标 skill：`skills/video-script/`（**被修改对象**，目录结构变成本 skill 的产物）
- 源 docx：用户给定路径，如 `/Users/hujie/Documents/企盛/客户知识库/{企业名}/引流型.docx` 等

## 输入要求

执行前必须向用户确认或推断以下三项：

| 项 | 必填？ | 说明 |
|---|---|---|
| docx 路径 | 必填 | 一份或三份（引流/种草/转化分开）。若只有一份综合文档，先按 `# 选题类型` 大标题识别属于哪一类 |
| 行业目录名 | 必填 | `references/` 下的子目录名，如 `国际物流`、`精密硅胶`。命名规则：与 docx 内容强相关的行业大词；用户不给时**先推荐再确认**（如「推荐 `国际物流`，还是 `货代`/`海运`？」） |
| 视频形式是否分模板 | 必填 | `混剪` 和 `真人出镜` **是否共用一套模板**。若共用 → 拍平成 `A1-xxx.md`；若分开 → 用 `{形式}-{类型}/` 二级目录 |

## 工作流

### Step 1：读 docx 摸底

用 `pandoc` 提取 docx 文本，弄清结构：

```bash
pandoc /path/to/{引流型,种草型,转化型}.docx -o /tmp/{引流型,种草型,转化型}.md
```

**预期结构**（与 docx 作者约定的事实格式）：
- `# {选题类型}类` 是大标题（如 `# 老板人设类`、`# 痛点类`）
- `（1）` `（2）` `（3）` 编号段落是各示例
- 同一份 docx 里可有多个 `# 选题类型` 块

**确认点**：
- docx 实际包含哪些「选题类型」（枚举出类名列表）
- 每个类型下有几个示例
- 与 SKILL.md 现有选题表的差异：新增哪些？删除哪些？

### Step 2：确认行业目录名

**必须由用户拍板**，不得自行命名。

推荐策略：从 docx 内容提炼行业大词，给 2-3 个候选让用户选：

- 海盛威 → 推荐 `国际物流`（也可 `货代`/`海运`）
- 精密硅胶 → 已有目录
- 音视频设备 → 已有目录

### Step 3：确认目录结构（扁平 vs 分层）

**默认扁平结构**（混剪/真人出镜共用模板时）：

```
references/{行业目录}/
├── A1-{选题名}.md
├── A2-{选题名}.md
├── ...
├── B1-{选题名}.md
├── ...
└── C1-{选题名}.md
```

**分层结构**（混剪/真人出镜分开时）：

```
references/{行业目录}/
├── 混剪-引流型/{选题名}.md
├── 混剪-种草型/{选题名}.md
├── 混剪-转化型/{选题名}.md
├── 真人出镜-引流型/{选题名}.md
├── 真人出镜-种草型/{选题名}.md
└── 真人出镜-转化型/{选题名}.md
```

### Step 4：分配选题编号

按 docx 实际类别映射到 A/B/C 编号：

- `引流型.docx` → A1、A2、A3、A4...
- `种草型.docx` → B1、B2、B3...
- `转化型.docx` → C1、C2、C3...

**命名规则**：
- 文件名 = `{编号}-{选题名}.md`（去「类」字，`老板人设类` → `A2-老板人设.md`）
- 选题名 = docx 中 `# {X}类` 的 `{X}` 部分
- **编号顺序按 SKILL.md 选题表的展示逻辑**（用户/创建者定义的分组顺序），**不是**按 docx 中 `（1）（2）（3）` 的物理顺序——docx 顺序只是写作顺序，选题表编号才是逻辑顺序
- 若 SKILL.md 已有该行业的选题表 → 沿用其编号；若是新行业 → 按分组展示逻辑分配（如 A 组先「行业热点」后「老板人设」等约定俗成）

### Step 5：写 md 模板文件

每个 docx 的 `# {选题类型}类` 块对应一个 md 文件，格式严格统一：

```markdown
# {选题名}

- 示例一

```
{docx 中（1）对应的全文原文}
```

- 示例二

```
{docx 中（2）对应的全文原文}
```

- 示例三

```
{docx 中（3）对应的全文原文}
```
```

**硬约束**：
- 标题用 `# {选题名}`（去「类」）
- 示例序号用中文 `- 示例一 / - 示例二 / - 示例三...`
- 示例内容用 ```` ``` ```` 代码块包裹，**逐字保留 docx 原文**（包括换行、错别字、占位符 `xx`），不改写不润色
- docx 中 `（N）` 序号转成 `- 示例N` 中文序号

### Step 6：处理「混剪 vs 真人出镜」

按 Step 3 确认结果执行：

- **共用**：跳过此步，扁平结构已天然共用
- **分开**：`cp -R 混剪-{类型} 真人出镜-{类型}` 拷贝三份，原样拷贝（docx 模板本身不分形式，先各放一份占位，后续再按形式差异化）

### Step 7：更新 video-script/SKILL.md 选题表

打开 `skills/video-script/SKILL.md`，定位 `## 选题` 一节，**整段替换**为按 docx 实际类别的清单。

**格式模板**：

```markdown
## 选题

展示选题类型,不要省略，不准省略遗漏，每个选题根据企业实际生成 1 个贴合的选题，输出表格格式：

```
🔵  引流型（易爆流量）
A1 {选题1} | A2 {选题2} | A3 {选题3} | A4 {选题4}

🟢  种草型（获客种草）
B1 {选题1} | B2 {选题2} | ... | B{N} {选题N}

🔴  转化型（获客转化）
C1 {选题1} | C2 {选题2} | C3 {选题3}

```
```

**同步要求**：
- 选题名与 md 文件名严格对应（去「类」）
- 编号与 Step 4 分配的一致
- **不要**保留 docx 里没有的选题（如 SKILL.md 原有的「噱头故事」「国产崛起」若 docx 没有，删掉）
- **不要**合并 docx 里分开的选题（如 `痛点类` 和 `爽点类` 是两块，拆成 B2 痛点、B3 爽点）

### Step 8：验证

完成后 `ls` 列出 `references/{行业目录}/` 全部文件给用户确认：

```bash
ls -la "/Users/hujie/Documents/skills/skills/video-script/references/{行业目录}/"
```

并向用户报告：
- 新建的文件数（扁平结构 = docx 选题类总数；分层 = ×2）
- SKILL.md 选题表更新点（新增了哪些类、删掉了哪些类、拆分了哪些合并项）

## 关键约束

1. **行业目录名必须用户确认**，不要自己定
2. **docx 原文不改写**——占位符 `xx`、错别字、口语化表达都保留
3. **SKILL.md 的「读模板」路径规则**——如果当前是扁平结构，确认 §读模板里的「优先路径」写的是 `references/{行业目录}/{选题编号}-{选题名称}.md`；如果是分层结构，写 `references/{行业目录}/{视频形式}-{类型}/{选题名称}.md`。**两种结构不能混着写**
4. **其他行业目录不动**——只改当前行业的目录，已有的 `精密硅胶/`、`音视频设备/`、`public/` 等不动
5. **公共降级路径保留**——SKILL.md 里 `references/public/` 的降级路径不动（那是兜底，不是当前行业）

|---|---|---|---|
| `references/国际物流/` | 海盛威引流/种草/转化 docx | 扁平（混剪真人出镜共用） | ✅ 已建 |
| `references/精密硅胶/` | 早期手工建 | 分层（混剪/真人出镜分开） | ⚠️ 旧结构未重构 |

| `references/public/` | 兜底模板 | 分层 | 保留不动 |

新行业一律用**扁平结构**；已有分层结构的行业**不动**，除非用户明确要求重构。

## 失败分支

- docx 结构和预期不符（没有 `# {X}类` 大标题、`（N）` 编号）→ 停下告诉用户实际结构，问怎么拆
- 用户对行业目录名、结构形式没确认 → 停下问，不要猜
- SKILL.md 里选题表更新后路径规则和实际目录结构对不上 → 停下指出冲突让用户定
- 已有同名行业目录 → 问用户是覆盖、合并还是另起名
