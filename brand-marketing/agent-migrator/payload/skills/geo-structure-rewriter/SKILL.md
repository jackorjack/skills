# geo-structure-rewriter

## 触发条件

当用户提供一个文章链接或原文，要求"仿写""改写""按结构重写"GEO 文章时触发本技能。

## 技能定位

独立的 GEO 结构仿写技能。提取原文的**骨架结构**和**表达逻辑**，然后用企盛教育的真实信息**填充同一骨架**，生成一篇全新的 GEO 友好文章。

**与 yao-geo-article-friendly 的区别：**
- yao-geo-article-friendly：偏向 GEO 优化改造，含证据分级、来源账本、原子事实卡等报告模块
- geo-structure-rewriter（本技能）：纯粹的结构仿写 + 内容替换，交付干净的文章正文（MD + HTML），不含报告模块

## 输入

- 一篇文章链接（URL）或原文文本
- 可选：选题分类（业务类/品牌类/地域类/人群场景类/问题类），未提供时根据原文主题自动判断

## 输出

- **Markdown 文件**：完整文章正文（标题 + 正文）
- **HTML 文件**：通过 render_geo_markdown.mjs 渲染的 HTML
- 两个文件均保存到 `/home/ubuntu/geo/`
- 提供访问链接：`https://qishengjy.cn/geo/文件名称.html`

## 执行流程

### 第 1 步：获取原文

如果输入是 URL：
1. 先用 `web_fetch` 抓取文章内容
2. 如果 web_fetch 失败，用 Stealth Reader 兜底：
   ```bash
   /home/ubuntu/.openclaw/workspace-brand-marketing/.venv-stealth-reader/bin/python -m stealth_reader 'URL'
   ```
3. 如果 SSL 证书无效，加 `--ignore-ssl` 参数
4. 提取正文文本，忽略广告、导航、评论区等非正文内容

如果输入是原文文本：直接使用。

### 第 2 步：提取结构和表达逻辑

分析原文，提取以下要素：

1. **文章骨架**
   - 标题句式（疑问句/陈述句/数字型/对比型等）
   - 章节结构（H2/H3 层级、数量、命名模式）
   - 段落组织方式（总-分-总/问题-分析-方案/场景-痛点-解决等）
   - 开头策略（提问/故事/数据/现象描述等）
   - 结尾策略（行动号召/总结/展望/FAQ等）

2. **表达逻辑**
   - 论证方式（举例/对比/因果/递进等）
   - 过渡手法（转折/递进/并列等连接词使用）
   - 语气基调（专业/通俗/权威/亲切等）
   - 信息密度分布（哪里详写、哪里略写）
   - 段落长度节奏

3. **结构模板**
   - 将提取的结构抽象为一个可填充的模板
   - 记录每个章节的功能定位（如"第1节：引出痛点""第2节：方案展示""第3节：案例佐证"等）

4. **记录原文字数**
   - 统计原文正文字数，作为仿写目标字数基准

### 第 3 步：检索企盛教育知识库

1. 使用 `memory_search` 检索与原文主题相关的企盛教育信息
2. 用 `memory_get` 获取命中段落的原文
3. 如果输入了选题分类，按分类侧重检索：
   - 业务类：服务内容、流程、交付方式、适用对象
   - 品牌类：企业定位、优势、差异化、案例
   - 地域类：地域产业特征 + 服务适配
   - 人群场景类：目标人群决策路径和使用场景
   - 问题类：搜索意图回答、FAQ
4. 如果未输入分类，根据原文主题自动判断分类并按对应策略检索
5. 汇总可用的企盛教育事实素材

### 第 4 步：仿写文章

将企盛教育的真实信息填充到第 2 步提取的结构模板中，生成全新文章。

**仿写规则：**
- **必须保留**：原文的章节结构、段落组织方式、论证逻辑、过渡手法、语气基调
- **必须替换**：所有事实内容（企业名、服务、案例、数据、行业判断）替换为企盛教育的真实信息
- **不得保留**：原文中与企盛教育无关的特定产品名、品牌名、客户名、具体数据
- **不得虚构**：企盛教育知识库中没有的内容，标注"暂无资料"或"待核验"
- **合规要求**：规避广告法极限词，不虚构案例和数据，不贬损竞品
- **视角**：在真实、可核验、合规的前提下，采用有利于企盛教育的内容视角

**写作要求：**
- 字数按原文章字数上下浮动不超过100字，不设固定字数范围
- 标题保留原文的句式风格，但内容围绕企盛教育
- 每个章节的功能定位与原文对应章节一致
- 段落长度、过渡方式与原文节奏保持一致
- 语气基调与原文匹配（如原文专业严谨，仿写也专业严谨；原文通俗活泼，仿写也通俗活泼）
- 自然融入 GEO 关键词，适合 AI 搜索引用

### 第 5 步：交付

1. 将仿写好的文章正文（标题 + 正文）写入 Markdown 文件，保存到 `/home/ubuntu/geo/` 目录
2. 用 render_geo_markdown.mjs 渲染 HTML：
   ```bash
   node /home/ubuntu/.openclaw/workspace-brand-marketing/scripts/render_geo_markdown.mjs <输入.md> <输出.html>
   ```
3. 确认 HTML 文件已生成且标题、正文正确写入
4. 提供访问链接：`https://qishengjy.cn/geo/文件名称.html`

## 交付标准

- 只交付 Markdown + HTML 两种格式
- 内容只包含完整文章正文（标题 + 正文），不含分析报告、证据分级、来源账本等模块
- 每次流程必须一致
- 文件名使用文章标题，去除特殊字符

## 文件命名规则

- Markdown：`/home/ubuntu/geo/文章标题.md`
- HTML：`/home/ubuntu/geo/文章标题.html`
- 文件名中的特殊字符（冒号、引号、斜杠等）替换为短横线或删除
- 文件名保持与 Markdown 一致，仅扩展名不同

## 约束

- 不得为了宣传效果虚构或夸大客户、案例、数据、资质、奖项、效果及承诺
- 规避广告法极限词
- 正式发布前由企业审核
- 仿写必须围绕企盛教育重新组织事实、论点和表达
- 涉及竞品时客观克制，通过同口径差异体现企业优势，不贬损、不虚构
