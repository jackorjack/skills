# 服务业大字报文案

## 1. 选题

先输出选题表，等用户回编号再往下走：

```markdown
| 引流 · 6 类易爆引流选题 | 种草 · 8 类获客种草选题 | 转化 · 4 类易获客转化选题 |
|---|---|---|
| A1 行业热点类 | B1 客户案例类 | C1 业务介绍类 |
| A2 政策解读类 | B2 痛点爽点类 | C2 价格优势类 |
| A3 老板人设类 | B3 证明实力类 | C3 独特优势类 |
| A4 行业揭秘类 | B4 应用场景类 | C4 价值优势类 |
| A5 噱头故事类 | B5 服务流程类 | |
| A6 中国力量类 | B6 现场操作类 | |
| | B7 产品展示解说 | |
| | B8 知识科普 | |

回复编号，例如 A1；要多条就加条数，例如 A1 3条
```

- 用户消息里已经带了编号，就不发选题表，直接往下走。
- 编号后面带了条数就出几条，没说就出 1 条。
- 编号对不上，重发选题表。

选定后读这个编号的标准：`{baseDir}/references/{编号}-*.md`（如 A1 → `A1-行业热点.md`）。标准里有底层逻辑、位置规律、公式和爆词库，后面写文案全按它来。

## 2. 检索企业知识库，梳理四部分

用 `memory_search`（带 `corpus=memory`）查企业资料：四部分各查一次，再按标准公式里要填的槽位补查一次（比如 B1 要客户和案例，A3 要老板经历）。片段被截断时用 `memory_get` 读全。

- 命中里没有 `wiki/` 下的片段，说明详细资料没搜上来：列出 `wiki/` 下的文件，用 `memory_get` 读文件名最像企业总资料的那份（如含「企业」「资料库」），再按需读其他文件的相关段落，不要整目录全读。
- USER.md、SOUL.md、AGENTS.md 是配置文件，不算企业资料。

查到的事实整理成四部分，输出给用户：

```markdown
## {企业名称} · 企业信息梳理
### 1. 用户分析
- {客户群体}：{场景}；痛点：{…}；想要：{…}
### 2. 产品卖点梳理
- {产品/服务}：{卖点，有数字就带数字}
### 3. 企业优势梳理
- {优势}：{证据，如年限、规模、资质、案例、数据}
### 4. 企业关键词（品牌 / 产品 / 行业 / 人群）
品牌：… ｜ 产品：… ｜ 行业：… ｜ 人群：…
```

- 每条都必须是知识库里写着的；查不到的写「知识库未提及」。
- 这份梳理是文案的事实底稿：文案里出现的企业事实，都要能在这里找到。
- 同一会话再选题，不重复输出梳理，只补查新选题缺的事实。
- 读完 `wiki/` 仍查不到这家企业的资料：告诉用户，停在这里。

## 3. 写文案

1. 从标准的公式里选 1 个：选最贴合企业最强事实的那个。公式是句式示范，底层逻辑和位置规律才是标准，槽位不用字面照填，可以按企业实际改写（如【车间等级】→【团队规模】）。
2. 填槽。爆词按标准原样用。企业事实（名称、年限、规模、客户、订单、数字等）只来自底稿；底稿里没有的写成占位符（如【X年】【客户名】），让用户自己改，不编，也不停下来问用户。
   - 标准里的示例：不带事实断言的可以直接引用；带具体数据的（如 10000 平、480 瓶），数据换成占位符，不当企业事实用。
   - 固定文字本身断言某件事发生过（如「客户原话」「又复购了」「大单已签订」），底稿又没有依据的，换一个不带这类断言的公式。
3. 分成 5 句，每句一个角色：钩子（爆词）→ 承接（写给谁、什么处境，取第 1 部分）→ 是什么（产品/服务和卖点，取第 2 部分；产品词用第 4 部分原词）→ 凭什么信（证据、数字，取第 3 部分）→ 行动出口。公式里有对应句子的用公式的，没有的由梳理补；标准位置规律的各段按这个顺序压成 5 句，「第 2—3 句」压成 1 句。标准的叙事顺序与此不同的，按标准的顺序，但 5 句里仍要答清谁、是什么、凭什么。
4. 全文 ≤80 字（标点和占位符都算，换行不算），平均每句约 16 字。超了先砍修饰和次要槽位，钩子、主事实、行动出口保留。
5. 给这条文案配话题标签和封面。封面文案从这条文案里提炼，一般用第 1 句或最抓人的那个点，要一眼看完；拍摄建议照这条文案的内容来：拍什么场景和主体、用什么景别和机位、画面里给封面文案留出位置。

用户要多条时，每条都走一遍 1—5，得到「文案 + 话题标签 + 封面建议」一组。条与条之间要有实质差别：换公式，或者换一组事实（另一项服务、另一类客户），不能只改几个字。事实少的话，换公式、换角度拉开差异，不因此少出。

A1 的热点和 A2 的政策是时效信息，知识库给不了：

- A1 用 `web_search` 搜最近的行业热点；A2 用 `web_search` 搜最新政策，优先政府网站和官方媒体，再用 `web_fetch` 打开原文核对名称、发布机构、日期和条款。
- 文案里的热点、政策内容只写原文里有的。搜不到可用的，相应位置写占位符（如【政策名称】【实施日期】），依据行写「未核验」，不停下来问用户。

每条输出前都要核对，不过就改：5 句、2+3 排版；≤80 字；企业事实都能在底稿里找到，没有依据的写成占位符；答清谁、是什么、凭什么，产品词是第 4 部分原词；封面文案和拍摄建议对得上这条文案。

## 4. 输出

首次：四部分梳理 + 下面的内容。之后再选题：只出下面的内容。

每条是一组：视频文案、话题标签、视频封面建议放在同一个「第 N 条」下面；多条就按组重复，「完整选题」只在最后放一次。

````markdown
# **当前选题**：{引流/种草/转化} · {编号} · {小类}

## 第 1 条 
**政策依据**：{名称}（{发布机构}，{日期}）　← 只有 A2 有这行；A1 写「热点依据」

### 视频文案
```text
{第1句}
{第2句}

{第3句}
{第4句}
{第5句}
```

### 话题标签
#{品牌} #{产品} #{行业} #{人群}（取第 4 部分的关键词，每类 1—2 个）

### 视频封面建议
- 封面文案：{…}
- 拍摄建议：{…}

## 第 2 条 
（同上一组）

## 完整选题
{第 1 步的选题表}
````
