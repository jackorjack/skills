## 何时使用

用户要求生成大字报短视频脚本或大字报文案时使用。

## 依赖的外部规则

企业事实先行、来源内部留痕默认不外显、检索一次优先（含「不得机械发出旧版固定的 3—4 条近似查询」）、结果复用、部分资料可用、四部分梳理结构与列名 → `skills/enterprise-profile/SKILL.md:11-15, 32-37, 64-90`。

除上述外，本技能的选题编号（§2.1）和生成规则全部在本文件内自带定义，不引用其他脚本技能。

**来源不外显（额外覆盖联网内容）**：企业资料部分见 `enterprise-profile`；本技能另覆盖 A1 联网核验结果和同事/同行对比数据——默认用户可见内容不得输出 `Source:`、`source`、来源路径、行号、引用标记、URL 或「来源」列。只有用户明确要求出处时，才展示最小必要来源。

## 本技能特有原则

- **参考风格不照抄**：学习模板的结构（包含短句字数）、开头噱头以及短句表达意思的连贯性；如果产品业务和模板示例相似，可直接套用，注意要把关键词换成适合自己行业、客户、产品的关键词。
- **表达质量优先级**：选题事实相关性 > 口语通顺和语义连贯 > 客户价值 > 噱头词形式 > 数字装饰。任何选题都要先选定可核验的主事实，再匹配有吸引力的开头；不能为了塞入噱头词、数字或产品词牺牲通顺度。
- **全选题通用噱头词与关联**：所有选题第一句用噱头词制造看点，至少带情绪、动作、反差、悬念或冲突之一，控制在 2-10 字；首句本身不要求独立事实依据，但须满足双重关联——**①与所选选题方向同域**：看到噱头词就能判断属于该选题（如发货/出库类词只用于 B7、揭秘/真相类词用于 A3、国产/出海类词用于 A5、案例/客户类词用于 B1、人物+反常类用于 A4、人设/身份/经历类用于 A2），不得用与本选题无关的噱头词凑数；**②与后文已核验事实自然关联**，不能是孤立噱头。第二句用已核验事实把首句的看点落到具体对象上；第三至第五句沿同一条逻辑继续解释。先定已核验主事实，再拟能由它承接的噱头首句；后文接不上就换首句。首句允许使用强情绪爆词和事件型表达，但第2句必须能用已核验事实承接该看点。
- **资料状态即生成门禁**：「待补充」表示缺少该选题专属事实，直接阻断生成。资料状态栏负责向用户透明展示事实完整度，并作为是否允许出稿的判定依据。
- **标签匹配**：话题标签围绕品牌、产品、行业、人群四类关键词生成。
- **批量事实覆盖门禁**：用户要求多条文案时，必须先建立“主事实—支撑事实—叙事角度”清单；同一完整事实句或近义改写不得反复出现。事实有限时可以通过不同叙事角度、适用场景和客户关切复用已核验事实，但不得新增未核验断言。


## 工作流

`企业梳理状态判定 → 四部分梳理 → 17 选题表 → 🔴等待唯一选题 → 读取模板 → 🔴草稿卡（每条必填，§4.5） → 🔴批量轮换预排表（N≥2 时必填，§4.6） → 正常生成（待补充选题停止并索要资料） → 批量事实覆盖检查（§4.2.1） → 15 项证据式自查（阶段五） → 输出`

不得合并或调换「企业梳理」和「选题确认」两个门禁。用户已在请求中给出唯一选题时可跳过等待选择，但不能跳过企业事实门禁。

## 阶段一：企业信息梳理与可见输出

### 1.1 企业梳理状态

进入技能时判定为以下三种之一：

| 状态 | 判定标准 | 下一步 |
|---|---|---|
| `NOT_STARTED` | 本轮对话没有完整企业梳理 | 执行 `enterprise-profile` |
| `SEARCHED_NOT_SHOWN` | 已检索或整理内部事实，但用户尚未看到四部分梳理 | 立即输出四部分，不得进入选题 |
| `PROFILE_VISIBLE_READY` | 本轮用户可见回复已完整出现四部分梳理、已知事实和缺项标记 | 直接进入阶段二，不重复检索或长篇梳理 |

以下情况**一律不算** `PROFILE_VISIBLE_READY`：
- 只调用了 `memory_search`、`memory_get`、文件读取或外部搜索；
- 只在内部整理事实表，没有向用户展示；
- 只在选题中零散使用企业数字；
- 只输出公司简介，缺用户分析、产品卖点、企业优势、企业关键词中的任一部分；
- 有企业事实但没有同步标注资料不足项。

### 1.2 执行梳理并输出

1. 按 `enterprise-profile` 执行检索与事实核验。
2. 只使用可在内部事实台账回指的事实；台账用于核验，不原样输出给用户。
3. 在同一次用户可见回复中，按 `enterprise-profile` 的四部分固定结构输出，四个标题必须齐全、不准省略：

```text
## 企业信息梳理
### 1. 用户分析
### 2. 产品卖点梳理
### 3. 企业优势梳理
### 4. 企业关键词（品牌 / 产品 / 行业 / 人群）
```

### 1.3 🔴 企业信息输出门禁

同时满足以下全部条件，才能置为 `PROFILE_VISIBLE_READY` 并进入阶段二：四个标题齐全 ✓；未把内部未核验内容写成企业事实 ✓；缺失部分已标注「建议补充」✓。

任一项不满足：停在阶段一补齐后重新检查，**不得先展示选题表**。

### 1.4 资料不足分支

| 条件 | 处理 |
|---|---|
| 企业名未知 | 只询问企业实际名称，不开始生成 |
| memory 未命中 | 按 `enterprise-profile` 的一次补检索与文件兜底流程执行 |
| 完全没有任何有效企业资料 | 明确告知知识库暂无内容；因无事实底座而停止，不进入伪造式生成 |
| 有部分有效资料 | 四部分照常输出；已知内容保留内部依据，缺项写「建议补充」；继续阶段二 |
| 某个选题缺专属事实 | 该行保留编号，资料状态写明具体缺口并标注「待补充」；用户选中后按 §2.4 输出缺口说明，并默认同步生成占位稿 |

**「关键事实不足」按具体选题判断。** 缺客户案例则 B1 标「待补充」并需用户补料后才生成；不影响其他已有依据的选题正常出稿。整表仅当「完全没有任何有效企业资料」时整体停止。

## 阶段二：选题

### 2.1 选题范围

输出下列 17 个编号：

```text
🔵 引流型（易爆流量）
A1 行业热点｜A2 老板人设｜A3 行业揭秘｜A4 噱头故事｜A5 国产崛起

🟢 种草型（获客种草）
B1 客户案例｜B2 痛点爽点｜B3 证明实力｜B4 应用场景｜B5 优势工艺｜B6 设备实力｜B7 现场发货｜B8 生产流程｜B9 产品展示

🔴 转化型（获客转化）
C1 业务介绍｜C2 价格优势｜C3 独特优势
```

### 2.2 选题输出格式

每个编号都必须出现，按上表三个分组标题分别输出；分组标题独立成行，也不要只输出编号。

| 编号 | 选题方向 | 贴合企业的选题 | 企业事实依据 | 资料状态 |
|---|---|---|---|---|
| A1 | 行业热点 | 按已核验企业事实填写 | 已核验事实简述 | 需联网核验 |

「贴合企业的选题」和「企业事实依据」两列按企业实际情况逐行填写，不附 `Source:`、路径、行号、URL 或「来源：」。「资料状态」取值三选一：

- `需联网核验`：仅 A1，且仅在用户选定后才联网核验最近一年来源，核验结果默认不在正文外显。
- `可生成`：已有足够企业事实。
- `待补充`：缺少该方向的案例、人物、订单、发货数量、价格或效果依据。必须写明「缺少××，需补料」，选题栏给出方向但标注不可生成，**不得伪装成可生成**。

「完整输出」指 17 个编号都在对应分组标题下出现且分组位置正确，不等于 17 个方向都要伪装成资料齐全。

### 2.3 🔴 CHECKPOINT · 选题确认

- 输出完整选题表后立即暂停；不读模板、不生成文案。
- 等用户明确选择一个或多个编号后继续。
- 选定后在读模板或出稿前，先用一行确认：`已选择：🔵 引流型（易爆流量）·A3 行业揭秘`；分组必须与编号一致。
- 选中 `待补充` 行：按 §2.4 输出具体缺口说明与所需资料清单，并**默认同步生成占位稿**（缺失事实用 `[ ]` 占位）；仅当用户明确要求「先补料再写」或「不出稿」时才停止生成。
- 用户请求中已含唯一选题：视为确认，但仍须完成阶段一和模板检查。

### 2.4 待补充选题：缺口说明 + 占位生成（默认联动）

选中 `待补充` 行时，同一回复内完成三件事：

1. **资料说明**：输出具体缺口与所需资料清单：

```markdown
## 资料说明
当前缺少具体{订单/客户案例/发货批次/价格数据/工序素材等}。请补充{所需资料清单}后可替换为实稿；下方已按模板钩型生成占位稿，`[ ]` 内为待填字段。
```

2. **占位生成**：读取该选题模板，按模板示例钩型生成文案；缺失的具体事实一律用 `[字段名]` 中文方括号占位（如 `[地点]`、`[数量]`、`[客户类型]`、`[工序名]`、`[X]%`），**不得编造值顶替**；已核验的企业通用事实（产品能力、规模、资质、案例方向）照常写入，不得一并占位。

3. **待填清单**：文案末尾列出全部占位符及每个占位符需要的内容，提示用户填实后方可发布。

**占位符合规**：占位符只能占「具体事实槽位」——时间、地点、数量、批次、价格、客户名、工序名、时长等；不得用占位符占产品能力或企业通用事实。生成时 `[ ]` 内只写字段名，不填任何值；自查表中占位符不计入「未核验断言」，但检查「占位符是否均为真实缺口字段」。

**例外停止**：企业级事实完全缺失（如企业名未知、无任何产品线资料）时仍停止生成；用户明确要求「先补料再写」或「不出稿」时按原停止流程。用户补齐资料后，将对应占位符替换为实稿重新输出。

## 阶段三：读取模板

用户确认选题后只加载对应选题模板；`待补充` 选题按 §2.4 进入占位生成流程，同样加载模板。出稿前读取 `references/dazibao-hotword.md`；优先选与已核验看点匹配、且第二句能兑现的噱头词作为母词，可原样使用、改写或扩展。无自然匹配时使用事实驱动的噱头词，不为满足噱头词数量硬凑，也不套用固定开头句式。

1. 从企业行业信息提取关键词，与 `references/` 子目录名模糊匹配。
2. 优先路径：`references/{行业目录}/{类型}/{选题名称}.md`。
3. 降级路径：`references/public/{类型}/{选题名称}.md`。
4. 文件名有别名时（如「生产流程/生产流程类」「老板人设/人设类」），先列出候选文件再选语义最匹配项，不凭空拼路径。

失败分支：行业目录和 `public/` 都无匹配 → 标注「无匹配模板」，告知用户后结合噱头词表和已核验事实写原创开头；选题模板为空或读取失败 → 不引用其中示例，说明原因后继续原创生成；选题与模板类型冲突 → 停止并要求重新确认，或由用户明确授权使用通用结构。

## 阶段四：生成文案

### 4.1 结构与字数

生成 4-6 个短句，默认写 5 句，总计 ≤80 字。每句承担一个角色：

```text
第1句：所有选题统一控制在2-10字，用噱头词写成，至少带情绪、动作、反差、悬念或冲突之一；不能只是产品标签或功能结论。优先从参考噱头词引用、借鉴改写，不直接出现客户行业，必须像正常口语而不是“噱头词+抽象名词”的拼接；首句无独立依据要求，但须满足两点——噱头词的语义域与所选选题方向一致（看到噱头词能认出选题），且能被第2句的已核验事实承接
第2句：紧接开头，用已核验事实直接回答首句提出的看点；有相关数字且能帮助回答时再放入
第3句：承接第2句，包含企业核心产品关键词
第4句：说明一个已核验的产品或企业事实
第5句：落到有依据且不量化夸张的客户好处；A1–A5 引流型选题的末句另按文档因果链要求带上「行动出口」——问句/招呼/承诺/起订提醒/咨询入口等（如“您需要吗？”“交个朋友。”“直接问我。”“需要的话找我。”），不能不收束
```

第2句到第5句逐句承接前句，每句都是完整句子，不能用孤立词充数。所有选题第1句须控制在2-10字，整篇仍须不超过80字。成稿必须通过朗读测试：连续读两遍不别扭，目标客户能立即听懂首句在说什么；通顺度约束见「本技能特有原则-表达质量优先级」。

第1句与第2句必须共同组成一个完整看点或逻辑关系：第1句给出情绪、冲突、提问、结果或价值等看点，第2句立即用具体对象和已核验事实把看点落到企业/产品实际（回答“凭什么/是什么/用在哪”）。只提到同一产品但落不实看点不算承接；第3句至第5句沿这一落点解释能力、应用、制造基础或客户价值。

### 单条文案排版（硬要求）

每条大字报正文必须严格按以下版式输出：

```text
第1句
第2句

第3句
第4句
第5句
```

- 第1句与第2句连续输出。
- 第2句结束后保留一个空行，再输出第3句。
- 第3句、第4句、第5句连续输出，中间不再插入空行。
- 多条文案之间可以用编号、标题或分隔线区分，但不得改变单条文案内部的上述版式。

#### 4.1.1 全选题通用噱头词与关联门槛

第1句默认同时满足“形式合规”和“传播噱头词有效”两层要求，所有选题统一执行：

- **噱头词有效**：第1句必须是 2-10 字的有噱头的事实首句，至少包含情绪、动作、反差、悬念或冲突之一；“注意看”“真相来了”以及“国产替代”“接入更简单”等没有观看张力的标签不能单独充当噱头词。**平铺记录判不合格**——只交代人物在做什么（“集成商跑了五家厂”）、只交代身份背景（“我在深圳做音视频”）、只抛事实标签（“信号全上网了”）均属平铺；首句须再叠加意外、代价、对比、紧迫、冲突任一要素才放行。
- **选题关联**：噱头词的语义域必须与所选选题方向一致——发货、出库、装车类噱头词只用于 B7；揭秘、真相、内幕类用于 A3；国产、出海、崛起、中外对比类用于 A5；客户、案例、合作类用于 B1；价格、成本、省钱类用于 C2；设备、产能、检测类用于 B6；工艺、流程类用于 B5/B8；人设、老板、经历类用于 A2。跨域借用须语义上仍落在本选题看点内，否则换同域噱头词。
- **立即承接**：写稿前先把第1句改写成它指向的看点，第2句须用可核验事实把该看点落到具体对象上；读者听完第2句不应还在问“跟这家企业什么关系”。第3至第5句继续沿同一落点解释。仅出现同一产品名、行业名或“支持某功能”不能算承接。
- **事实边界**：情绪可以有力度、噱头词可无独立依据；首句允许使用强情绪爆词制造看点，第2句起必须能被已核验事实承接。不能承接时换噱头词，不是删噱头。
- **噱头词匹配**：若使用噱头词，第1句应能回指 `references/dazibao-hotword.md` 或对应选题模板；不要求噱头词本身有事实依据，只要求能被第2句的已核验事实自然关联。没有自然匹配时，使用事实驱动的自然反差，并在内部标记“无匹配自然噱头词”。
- **不合格关联**：如 B7“今天发货！→支持小批量定制”、C2“省一半！→支持芯片级定制”，虽有真实产品事实，但首句与第2句语义割裂、接不住看点；先换首句或换承接角度，不能把产品介绍硬接在后面。第3至第5句跳到无关看点也须重写。

“专业、严谨”约束的是事实层和客户价值层，不等于删除第1句的传播噱头词；不得靠虚构数据、低俗内容制造点击。

#### 4.1.2 引流型选题固定因果链（A1–A5 生成时强制）

文档《大字报类型标准化条件·引流》为每个引流选题钉了一条固定因果链。生成 A1–A5 文案时，第1–5句必须按对应因果链顺序覆盖各环节——**首句落在第一环，末句必须含行动出口/承诺/招呼收束，中间环节顺序不得跳环、不得倒序**。链条长于5句时允许一句承担相邻两个环节，但不得缺环。

**各选题固定因果链**（文档原句照录）：

- **A1 行业热点**：热点信号 → 格局/规则变化 → 谁受影响 → 旧风险/旧痛点 → 新方案上位 → 可验证证据/保障 → 普及/行动出口

**5 句映射表**（操作层，用于草稿卡与自查；不改链条本身）：

### 4.2 噱头词驱动的原创开头（执行步骤）

噱头词有效性、立即兑现、事实边界、噱头词匹配的门槛全部按 §4.1.1 执行，本节只定义执行顺序。A1–A5 按 §4.1.2 先定变体与公式再写：

1. 先从事实台账选一个有依据的产品能力、客户痛点或应用事实，写清开头之后要落到的具体对象。
2. 查 `references/dazibao-hotword.md` 和对应选题模板选定母词或事实驱动噱头词——母词的语义域必须与所选选题一致（见 §4.1.1 选题关联）；内部核对「首句的选题归属与看点 → 第2句的事实承接 → 第3至第5句的连续解释」，不通过则按 §4.1.1 重写首句或整条。
3. **先拆噱头词型再写**：读取选题模板后，先拆解示例首句的噱头词型类别（围观惊叹/质疑反问/揭秘陈述/痛点提问/事件悬念/自述开场/数据前置），生成时优先沿用模板示例的同类噱头词型；仅当示例噱头词型与已核验事实不匹配时才换噱头词型，换噱头词型时从噱头词表选同语义域母词。
4. 批量输出时轮换事实对象、叙事角度、噱头词类别和句式节奏；不能只把同一个词换成近义词、只改产品名或所有文案都使用同一种开头。

### 4.2.1 批量规模与事实覆盖检查

用户要求 2 条及以上时，生成前必须执行本检查；用户要求 1 条时跳过。

1. 读取用户要求的数量 `N`，建立内部事实池。事实池至少包含：主事实、支撑事实、适用场景、可用数字、目标客户和叙事角度。主事实必须是可独立核验的产品能力、应用场景、客户痛点、案例、企业经历、工艺或交付事实；同一事实的换序、同义改写、拆句和合句仍算同一个主事实。
2. 每条文案先分配 1 个主事实和 1 个叙事角度，再写正文。优先轮换相互独立的主事实；事实池有限时，可以复用已核验主事实，但必须更换真实的叙事角度、适用场景或目标客户关切，不能只改产品名或近义词。数字、接口、安装方式等只是支撑事实，不能把同一卖点拆成多个“不同事实”来伪造事实多样性。
3. `N >= 6` 时，至少轮换 6 类噱头词型结构或噱头类别，并至少轮换 3 种叙事角度（如情绪感叹、提问悬念、痛点警示、结果前置、对比冲突、价值承诺、制造基础、应用场景）；同一个噱头词母词默认最多使用 2 次。相同的连续 8 字以上事实短语不得出现在多条文案中，必须保留的产品名称除外。A1–A5 另按 §4.6 轮换子结构变体。
4. 事实池不足时，可扩展到同一选题内相邻且已核验的事实，例如从产品功能扩展到适用场景、定制方式、稳定性或客户选型价值；不得把关键词表、行业常识或推测当作企业事实。
5. 当用户明确要求 `N` 条时，应在已核验事实范围内尽量完成 `N` 条。事实池有限时，允许通过不同叙事角度、适用场景、目标客户关切和句式节奏复用事实；每条正文的事实层仍须能回指事实台账，噱头词不能成为新增未核验结果的依据。
6. 批量事实覆盖检查未通过时，禁止进入最终 15 项自查；必须先更换主事实、叙事角度、适用场景或目标客户关切，直到每条都能回指已核验事实且表达不机械重复。


### 4.4 硬要求

- **产品关键词（清单制，不是固定枚举）**：每条必须含 1–2 个**阶段一「4. 企业关键词 → 产品关键词」清单内的产品实体名**；清单随企业知识库产品矩阵动态更新，不预设固定数量。判定方式：逐条在草稿中点出实际用了哪个清单内实体名；点不到名（只写“设备/方案/一体机/产品”裸用、能力词如“芯片级定制/源头制造”、行业概括词如“音视频设备”）一律算缺。**能力词、企业属性词、业务模式词不得顶替产品词**——它们可作第3-5句的支撑事实，但不能单独满足本条要求。
- **卖点数量（硬要求）**：每条文案必须包含 **1–2 个卖点**。卖点 = 事实台账中能给客户带来具体利益的已核验能力条目（如“POE 供电一根网线上墙”“15 分钟搭 30 席”“底层协议按项目写”“双备份”“8K 信号 IP 化”）。**超过 2 个判堆砌裁剪；为 0 个判空洞重写**；情绪词、身份词、空泛承诺不得顶替卖点。**卖点缺数据/缺依据时**——若该卖点所需的具体数字、场景、订单、效果在台账中没有回指，用 `[字段名]` 中文方括号占位（如 `[X]分钟`、`[X]席`、`[地点]`），并在文案末尾“待填清单”列出每个占位符需要什么；不得编造值顶替、也不得写成“支持某功能”式空话。
- **禁用卖点（硬要求）——数量单位+销售弹性类**：「一台也能定制」「一台也能发货」及同义表达**不得作为卖点出现在第1–5句任何位置**，也不得改写、拆句或换说法规避。
    - **同义表达清单（不全枚举）**：一台起订 / 一台起发 / 一台起售 / 一台也卖 / 一台包邮 / 一台拿样 / 一台也是批发价 / 单台定制 / 单台发货 / 单台起订 / 单台现货 / 一件定制 / 一件起发 / 一件起订 / 一件包邮 / 1台起订 / 1台也发 / 单个起售 / 一台可做 / 单台可做 等。
    - **判定语义**：「数量单位词（一/单/1/单台/一件/单个/1台/1件）+ 销售弹性动词（起订/起发/起售/定制/发货/也卖/也发/包邮/批发价/现货/拿样/可做）」整族禁用；只要卖点落在「降低起订门槛 / 强调单台可买可发」这个口径上即判违规，不论措辞怎么变。
- **句式骨架多样化（全篇硬要求，不只首句）**：批量输出（N≥2）时，**任意一个句子位置（第 1–5 句）不得出现跨条重复的固定句式骨架**。判定方法：把 N 条同一位置的句子并排，去掉事实词（产品名、数字、场景名）后若骨架相同（如全部末句都是「做XX的，…」「一台顶XX」「XX全在这」「XX才稳」），即判违规。第 5 句/末句尤其禁止统一使用「做+身份+的，+劝告」模板；客户身份识别允许三种自然方式轮换——①第二人称「你/您」直接称呼；②身份词自然嵌入叙述（“项目验收那天，甲方一次签完字”）；③场景处境指认（“到扩容那天才发现矩阵不够”）。同一条内只允许使用其中一种，不得叠用。
- **说话方立场锁定**：以厂家为主体的选题（B3 证明实力、B5 优势工艺、B6 设备实力、B7 现场发货、B8 生产流程、B9 产品展示及 C 组转化型）统一用「我们/咱家」作说话方，禁止写成「他家/这家厂」等第三方旁观口吻；A2 老板人设用第一人称「我」；引用客户或来访者视角时须明示主体（「客户说」「来的人说」），不得让厂家自述与第三方转述混用。
- 数字按事实需要自然使用，默认 0-2 个阿拉伯数字；只有数字能直接支撑当前看点时才使用。数字不是硬性装饰要求，不能为了满足数量而挪用其他选题事实、拆分同一数字或制造生硬表达。
- **句子成分完整（朗读硬门槛）**：每句必须是完整句子，80 字是整篇上限不是逐句上限，禁止为压字数砍成分。四类病句一律重写——①虚指代悬空："这个环节/这道/这台"后不接具体对象，占位稿中 `[工序名]` 类占位符不得与"这个/这道"同用；②术语缩略："打上牌"应为"打上品牌"、"手拉手"应为"手拉手连接"，双字术语一个字不能省；③技术现象拟人失真：屏"死了"应为"黑屏/死机"，拟人词不得替换准确技术词；④成分残缺：主谓宾任一被砍（"没法按老干了"应为"没法按老方法干了"）。逐句朗读卡住即重写该句。
- 全篇要让目标客户认出这是写给他的：默认用「你/您」直接称呼，或点出他的身份与处境（如采购、老板、车间）。A2 老板人设等以主体自述为主的选题用第一人称，但落点仍须回到目标客户关心的问题。
- 必须落到客户好处，但只能做有依据的定性表达；无资料不得承诺具体降本、效率或投诉降幅。
- 不出现企业品牌名和「私信」（本技能独有，外部无此规则）。公式中“出口：私信/加微信”是行动出口的类型标注，不是成稿用词——落到第5句时改写为“需要的话直接问我/找我/喊我/随时找我”这类不出平台词的表达。
- 不讲 `±0.02mm`、百分比等术语，用普通观众能懂的大白话；交期不作为卖点或痛点。
- 批量输出不得只替换产品名，句式和叙事结构都要有差异；还必须通过 4.2.1 的主事实数量、事实重复上限、短语重复和噱头词轮换检查。

预排表排不出 → 回到事实池扩列，或向用户说明数量上限；不得为凑条数重复主事实、也不得为凑条数让末句结构全部相同。

## 阶段五：生成后自查

本阶段是出稿硬门禁，不得省略、概括或用统一结论代替逐条检查。每条文案必须先完成下表 15 项自查；任一项不通过，先重写该条并重新逐项检查，未全部通过不得向用户展示文案。

**核心改动：证据式自查。** 自查表不是“打勾确认”，而是“填证据验证”——每一项都要求从本条正文中**摘出具体内容**填入「证据」列。填不出具体内容 → 该项直接判 ❌，不得以「我觉得有」「应该有」通过。

**拦截式执行**：自查是**生成前拦截**，不是生成后追认。任一项的「证据」列填不出本条正文里的**原文摘录** → 该条直接作废重写，不得先写完正文再回头补证据。噱头词有效性的证据 = 首句原文 + 明确指出它含「情绪/动作/反差/悬念/冲突」中的哪一个具体词；卖点合规的证据 = 卖点原文位置 + 台账出处；末句结构的证据 = 末句原文 + 与同批其他条末句并排去事实词后的骨架对照。噱头词型名、类别名、“应该算合规”这类描述一律不算证据。

每条文案独立一张自查表，批量时逐条过。任一项 ❌：不展示该版，立即重写并重新检查，直到全部 ✅。**证据不可压缩**：证据列必须逐条填写本条正文的原文摘录与台账出处，禁止以「✅」「通过」「10/10」「全部合规」等结论替代证据；批量时可合并同一检查项，但每条必须有自己的证据行，不得跨条合并或笼统写「10/10 均为✅」。最终输出时先展示自查表（证据列保留原文摘录），再展示文案。
